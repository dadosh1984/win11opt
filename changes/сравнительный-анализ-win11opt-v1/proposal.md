# Предложение — v1.6.0: сравнительный анализ и план фич

## Цель
На основе сравнительного анализа с аналогами — сформировать и реализовать
3–5 новых фич v1.6.0, беря лучшие идеи конкурентов и адаптируя их под
наш стек (Python 3.11+, single-EXE, dry-run по умолчанию, без сети).

## Конкурентный анализ

### 1. Win11Debloat (github.com/raphire/win11debloat) — open source, MIT
**Что есть хорошо:**
- Очень простой "одностраничный" подход — все твики в одном PS-скрипте, GUI добавили позже.
- Хорошая интеграция с официальными MS-скриптами (Win-Debloat-Tools как upstream).
- Прозрачный список изменений в README, без surprises.

**Что есть плохо:**
- Нет системы правил в YAML, нет rollback — изменения необратимы (только restore point).
- Нет пресетов под разные сценарии (Privacy / Gaming / Balanced).
- Нет bench — нельзя измерить эффект.

**Что взять:**
- Документацию "что меняется" в README (наш `ms_doc_url` это уже закрывает лучше).
- **Простой "Quick Win" режим** (см. фичу P0).

### 2. Chris Titus Tech's Windows Utility (CTTWU) — open source, MIT
**Что есть хорошо:**
- Очень популярен (~30k stars) благодаря YouTube.
- Есть tabbed UI (Tweaks / Install / Config) — интуитивно.
- Поддержка winget-install.

**Что есть плохо:**
- Winget-install вызывает сеть (нарушает наш privacy-first).
- Мало правил в категории "privacy" по сравнению с Win11Debloat.
- Категории tweaks — фиксированные, не расширяемые.

**Что взять:**
- **Категории с подкатегориями (collapsible)** в GUI (см. P1).
- Tabbed-структуру НЕ берём — текущая плоская структура проще и понятнее.

### 3. hellzerg/optimizer — open source, MIT (C# .NET 8 + WPF)
**Что есть хорошо:**
- Зрелый GUI на WPF — самый качественный из open-source.
- Встроенный GPO-редактор (mmc-like).
- Sports / Privacy / Gamer пресеты.
- Имеет свой "System Information" дашборд.

**Что есть плохо:**
- C# стек → крупный EXE (~20MB), требует .NET runtime в системе или self-contained сборку.
- GPO-редактор избыточен — большинству пользователей не нужно.
- Нет YAML-правил (hard-coded).

**Что взять:**
- **System Information дашборд** (см. фичу P0).
- Идею пресетов под сценарии (у нас уже есть 5 пресетов — закрыто).

### 4. SophiApp — open source, MIT (C# + Fluent Design)
**Что есть хорошо:**
- Fluent Design (Win11 native) — выглядит "родным".
- Подробные тултипы для каждого правила.
- Открытая wiki с описанием каждого твика.

**Что есть плохо:**
- C# стек (та же проблема с EXE).
- Wiki отдельно от кода — может расходиться.

**Чужие фичи → наши:**
- **Тултипы с описанием** (наш `ms_doc_url` уже лучше — ссылка на вендора).
- Wiki дублировать не нужно.

### 5. WinAero Tweaker — freemium ($15 платная)
**Что есть хорошо:**
- Самый зрелый (>10 лет разработки).
- Очень много категорий (Themes, Taskbar, Explorer, Modern UI, Old Explorer).
- Подробные скриншоты до/после.

**Что есть плохо:**
- Платный → нет доступа к коду, нельзя верифицировать что делает.
- Закрытый код — privacy red flag.

**Что взять:**
- **Категорию Themes (визуальная стилизация)** — у нас частично есть в visual.*,
  но нет отдельной группы для тем/иконок/курсоров.
- **Before/After скриншоты** — не берём (вне scope).

### 6. O&O ShutUp10 — freemium
**Что есть хорошо:**
- Специализация на privacy-твиках (телеметрия, реклама).
- Простой checkbox-интерфейс без пресетов — каждый твик отдельно.

**Что есть плохо:**
- Платный для расширенных фич.
- Нет rollback, нет bench, нет пресетов.

**Что взять:**
- **Privacy-чекбоксы "по одному"** — у нас пресеты уже лучше (один клик = 30 твиков).

## Наша уникальность (что есть только у нас / мы делаем лучше)

1. **YAML-правила + валидация** — расширяемость без перекомпиляции. Никто из
   конкурентов этого не делает (все hard-code твики).
2. **ms_doc_url → learn.microsoft.com** — каждое правило ссылается на вендора,
   это редкая прозрачность.
3. **Snapshot + rollback + dry-run + restore point** — **четыре уровня защиты**
   одновременно. У конкурентов — максимум 2.
4. **Bench с JSON diff-report** — измеримый, воспроизводимый результат
   "до/после" с возможностью хранить историю.
5. **i18n EN+RU через gettext (.po/.mo)** — для русскоязычной аудитории
   это уникально (все конкуренты английские).
6. **Privacy-first: ноль сетевых вызовов** — нет телеметрии, нет update-checker,
   нет "отправить отчёт". Verified по коду.

## Где отстаём (must-fix vs nice-to-have)

| Где | Severity | Причина |
|-----|----------|---------|
| GUI без System Information дашборда | **P0** | Пользователь не видит, что оптимизирует — слепое применение твиков |
| Нет "Quick Win" / Safe Mode пресета | **P0** | Новичкам страшно применять "Aggressive" |
| Нет undo для apply без snapshot | P1 | snapshot есть, но если забыл — нет второго шанса |
| Нет экспорта отчёта в HTML | P2 | Сейчас JSON, красивый отчёт нужен для шеринга |
| GUI не использует `services_by_state` | P2 | Не показывает разбивку Running/Stopped |
| Нет "что нового" / changelog в GUI | P2 | Пользователь не знает о новых правилах |

## Польза для пользователя (1-2 строки)

> **Безопасная и измеримая оптимизация Windows 11 без сетевой телеметрии** —
> пользователь видит состояние системы ДО (bench + System Info), выбирает
> пресет или YAML-правило, видит dry-run дифф, может откатить через snapshot.
> Всё прозрачно: каждое правило ссылается на официальную документацию Microsoft.

## План фич v1.6.0

### P0 (must-have, реализуем сейчас)

#### 1. **System Information дашборд** (идея от hellzerg/optimizer)
- `win11opt info` — CLI команда + GUI вкладка.
- Показывает: OS version, build, arch, RAM total/free, CPU model/cores,
  disk (C: free/total), GPU, Windows edition, install date, uptime.
- Не делает никаких изменений — только чтение.
- ponytail: rung 4 — пользователь видит что оптимизирует, снижает страх изменений.

#### 2. **Quick Safe пресет** (идея от Win11Debloat + CTTWU)
- Новый пресет `safe` — 5-7 самых безопасных твиков (visual.disable_animations,
  telemetry.advertising_id, services.disable_diagtrack, ui.search_hidden,
  power.ultimate_performance). Низкий риск, заметный эффект.
- `win11opt apply --profile safe --dry-run` — рекомендованная точка входа для новичков.
- ponytail: rung 5 — снижает барьер входа, расширяет аудиторию.

### P1 (хорошо бы)

#### 3. **GUI: collapsible категории + поиск** (идея от CTTWU)
- Группы правил в GUI сворачиваются/разворачиваются.
- Поиск по id/description.
- ponytail: rung 4 — при 52 правилах без поиска тяжело.

### P2 (отложить, если времени нет)

#### 4. **HTML bench-отчёт** (наш формат, расширение JSON)
- `bench report --format html` → стилизованный HTML с графиками (без JS — статичный SVG).
- ponytail: rung 4 — красиво шерить с друзьями, доказательство эффекта.

#### 5. **GUI: показывать `services_by_state`** (наша фича, недоделана в GUI)
- В bench-вкладке GUI показать "Running: 80 / Stopped: 40 / Disabled: 5".
- ponytail: rung 4 — закрывает наш собственный tech-debt.
